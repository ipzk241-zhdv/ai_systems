# Спільне сховище файлів

Вебсторінка дозволяє завантажувати файли з телефона/ПК, знаходити їх за назвою,
скачувати й копіювати команду для запиту до ШІ в Telegram. Усі дозволені користувачі
бачать одні й ті самі файли. Завантаження не запускає аналіз автоматично.

Інтерфейс працює як файловий менеджер: папки й підпапки, навігаційний шлях,
перейменування та переміщення через «⋮», список або плитки, сортування, пошук,
фільтри документів/зображень, завантаження кількох файлів із прогресом.
Наявні файли автоматично стають файлами кореневої папки, їхні номери не змінюються.

## Де налаштовувати

Локально: `mkr/solution/.env`. На поточній Oracle VM:
`/home/ubuntu/ai_systems/mkr/solution/.env`. Файл `.env.example` — приклад, його
редагування не змінює робочі параметри. Змінні середовища мають пріоритет над `.env`.

| Параметр `.env` | Що змінює | Типове значення |
| --- | --- | --- |
| `FILES_ENABLED` | Увімкнути сайт і команди сховища | `0` (вимкнено) |
| `FILES_ALLOWED_USER_IDS` | Дозволені Telegram user_id через кому | Порожній список |
| `FILES_PASSWORD_HASH` | Хеш спільного пароля; генератор нижче | Не заданий |
| `FILES_PUBLIC_URL` | Адреса сайта для посилань із бота | `http://127.0.0.1:8080` |
| `FILES_PORT` | Локальний порт вебсервера | `8080` |
| `FILES_STORAGE_LIMIT_MB` | Сумарний обсяг файлів, МБ | `5120` (5 ГБ) |
| `FILES_MAX_FILE_MB` | Максимум для одного файла, МБ | `2048` (2 ГБ) |

Обсяг сховища можна встановити від 1 до 1 048 576 МБ, одного файла — від 1 до
16384 МБ. Це програмні верхні межі, а не гарантія наявності місця на VM. Місце наперед
не резервується; перед завантаженням також перевіряється фізично вільний диск із
резервом 64 МБ. Індикатор на сайті показує використаний обсяг, налаштовану квоту
й доступне місце з урахуванням диска. Зниження квоти не видаляє наявних файлів.

Після зміни порту, адреси чи максимального розміру файла перезапусти `news-bot`.
Зміни whitelist і хешу пароля перевіряються при кожному зверненні. Посилання на вхід
діє 5 хвилин, сесія — 2 години; ці технічні терміни поки задані в `file_store.py`.

## Команди

- `/id` — показати власний Telegram `user_id` (не `chat_id`).
- `/files` або «Файли» — список останніх файлів і посилання для входу на сайт.
- `/file 12 поясни головне` або `Файл 12: знайди суму витрат` — питання до файла №12.

Команди сховища працюють тільки в особистому чаті з ботом. У Guest Mode бот запропонує
перейти туди. Відповіді за файлами не потрапляють до звичайної історії чату в пам’яті;
наступне питання про файл теж надсилай через `/file`.

## Доступ

Список `FILES_ALLOWED_USER_IDS` містить числові ID, розділені комами. Кожна людина
дізнається свій ID командою `/id`. Бот бере особу з `message.from.id`, а не з тексту
запиту чи номера групи. Сховище не обмежує доступ до інших функцій бота.

`/files` видає дозволеному користувачу одноразове посилання на 5 хвилин. На сайті
потрібен ще й спільний пароль. ID не вводиться вручну: його вже підтвердив бот.
Посилання не пересилай іншим. Секретна частина розташована у фрагменті URL (`#access`),
не надсилається в HTTP URL і прибирається з адресного рядка після відкриття.

Сесія діє 2 години. Cookie має HttpOnly/SameSite=Strict, а для HTTPS — Secure.
Завантаження вимагає CSRF-токен і правильний Origin. Видалення ID зі списку одразу
закриває доступ і через сайт, і через бота; заміна хешу пароля завершує старі сесії.
Правила перевіряє Python-код перед відкриттям файла і перед зверненням до моделі.
ШІ отримує тільки вибраний файл/уривки, не має інструментів для довільного доступу
до диска, видалення файлів чи зміни прав. Вміст документів вважається недовіреними даними.

## Увімкнення на Oracle

Основний бот працює як раніше; сховище за замовчуванням вимкнене. Вебсервер і PDF
потребують Python 3.10+; на поточній VM використовується Python 3.12.

З каталогу `mkr` встанови окремі залежності (Ubuntu 24.04, без venv):

```sh
python3 -m pip install --user --break-system-packages -r solution/requirements-files.txt
```

Якщо pip ще не встановлений: `sudo apt install python3-pip`.
Наявний CI не встановлює нові додаткові залежності автоматично — це одноразовий крок.

Згенеруй хеш пароля командою з каталогу `mkr`:

```sh
python3 solution/file_store.py
```

Скрипт попросить пароль двічі, від 12 символів, і покаже рядок
`FILES_PASSWORD_HASH=...`. Скопіюй весь рядок буквально в `solution/.env` через редактор,
без виконання в shell. Пароль зберігається як PBKDF2-хеш із сіллю, не відкритим текстом.
Сам пароль передай дозволеним користувачам поза Git.

Додай в `solution/.env`:

```dotenv
FILES_ENABLED=1
FILES_ALLOWED_USER_IDS=123456789,987654321
FILES_PASSWORD_HASH=скопійований_рядок_хешу_без_повторного_FILES_PASSWORD_HASH
FILES_PUBLIC_URL=http://127.0.0.1:8080
FILES_PORT=8080
FILES_STORAGE_LIMIT_MB=5120
FILES_MAX_FILE_MB=2048
```

ID вище — приклади; заміни їх реальними з `/id`. Рядок із хешем заміни результатом
команди цілком. Перезапусти той самий сервіс:

```sh
sudo systemctl restart news-bot
sudo systemctl status news-bot --no-pager
```

Вебсервер працює окремим потоком цього ж процесу, слухає **тільки 127.0.0.1:8080**.
Окремий daemon не потрібен, чинний systemd-сервіс може писати в `.runtime`.

## Прямий HTTPS без домена

На поточній VM налаштована адреса **https://141.147.21.157** з довіреним
сертифікатом і автоматичним поновленням. Для входу отримай нове посилання через
`/files` у боті й уведи пароль. SSH-тунель не потрібен.

Nginx приймає порти 80/443, а Python-сервер залишається на `127.0.0.1:8080`.
Після зміни `FILES_MAX_FILE_MB` чи `FILES_PORT` додатково до перезапуску бота виконай
команду з актуальної версії репозиторію:

```sh
sudo python3 /home/ubuntu/ai_systems/mkr/deploy/direct_files_https.py --refresh-proxy
```

Це синхронізує порт і розмір файла з Nginx. Обслуговування сертифіката описане
в `mkr/deploy/HTTPS.md`. Cloudflare-тунель вимкнений.

## Локальна перевірка через SSH як запасний варіант

Якщо тимчасово працюєш без публічного HTTPS, можна повернути локальний
`FILES_PUBLIC_URL=http://127.0.0.1:8080` і відкрити SSH-тунель. Не публікуй порт
8080 напряму й не використовуй відкритий HTTP для пароля.

Перевірити сайт із комп’ютера до налаштування HTTPS можна SSH-тунелем:

```text
ssh -N -L 8080:127.0.0.1:8080 -i "D:\Downloads\ssh oracle\ssh-key-2026-11-17.key" ubuntu@141.147.21.157
```

Залиш цю консоль відкритою, надішли боту `/files` і відкрий отримане посилання
`http://127.0.0.1:8080/#access=...` на цьому ж комп’ютері. Для цього режиму в `.env`
залишай локальний `FILES_PUBLIC_URL`. Звичайний публічний HTTP конфігурація відхиляє.

## Формати й обмеження

Зберігати/скачувати можна будь-які файли: типово до 2 ГБ на файл і 5 ГБ на все сховище;
обидва обмеження змінюються в `.env`. Передача й запис ідуть частинами, без утримання
всього великого файла в пам’яті. Максимальна вкладеність папок — 32 рівні.
ШІ підтримує UTF-8 TXT/MD/CSV/JSON/LOG, PDF із текстовим шаром, DOCX та JPEG/PNG/WebP
(картинки для аналізу до 8 МБ). Скановані PDF спочатку перетвори на картинки.
Архіви, програми та інші формати тільки зберігаються — сервер їх не виконує.
Видалення файлів у цій версії ще немає.

Для файла на 1,5 ГБ достатньо `FILES_MAX_FILE_MB=2048`, якщо у загальній квоті й на
диску вистачає місця. Передача на сервер поки не підтримує відновлення після обриву;
при обриві незавершений файл відкидається, і його потрібно надіслати заново.
Waitress спочатку буферизує тіло запиту в тимчасовий файл, потім застосунок копіює
його блоками до сховища. Тому на час завантаження потрібне місце приблизно на дві
копії файла (плюс вільне місце для ОС), хоча в пам’яті весь файл не утримується.

Скачування підтримує одиничні HTTP Range, ETag/If-Range та часткові відповіді 206.
Браузер або менеджер завантажень із підтримкою цих механізмів може продовжити
скачування з потрібного байта; автоматичне продовження залежить від клієнта. Для
кожного нового запиту знову перевіряються сесія і whitelist. Якщо сесія закінчилась,
спершу увійди повторно; вже розпочате скачування не обривається через її спливання.

Для великих документів витягується не більше 100 000 символів; модель отримує до
5000 символів вибраних за словами запитання. Бот явно позначає аналіз за уривками.
Це простий пошук фрагментів, не гарантія аналізу всього документа. Для повної перевірки
великої таблиці/документа розбий його на частини й перевір важливі числа самостійно.
Текстові документи використовують звичайний LLM_PROVIDER/LLM_MODEL, картинки —
Groq/VISION_MODEL. Вибраний вміст передається відповідному провайдеру лише за командою.

Файли лежать під випадковими назвами в `solution/.runtime/files/blobs`, метадані,
хеші посилань і сесій — у `solution/.runtime/files/files.sqlite3`. Оригінальна назва
ніколи не використовується як шлях на сервері. PDF/DOCX читаються окремим процесом
із таймаутом, а на Linux також з обмеженням пам’яті й CPU.
Файли, БД і `.env` не входять у Git/ZIP-пакет. Наявні резервні копії новин не є
резервною копією сховища — для важливих матеріалів потрібна окрема копія `.runtime/files`.

SQLite не містить вміст файлів: `files.sqlite3` зберігає тільки метадані та зв’язки.
`blobs` — звичайна тека на диску з двійковими файлами під випадковими службовими
назвами. Оригінальні назви містяться в БД і повертаються при скачуванні. Для резервної
копії потрібні і ця тека, і БД, щоб збереглися назви, папки та номери для бота.


## Завантаження цілої папки з комп’ютера

Натисни **«Завантажити папку»** або перетягни папку з провідника у панель файлів.
Вибрана папка разом із підпапками й файлами з’явиться у поточній папці сховища.
Chrome/Edge через HTTPS підтримують вибір із порожніми підпапками; запасний
браузерний вибір через `webkitdirectory` передає тільки файли, тому порожні
папки не зберігає. Перетягування папок також залежить від підтримки браузером
Directory Entries API. Це вебфункція; безпосередньо в Telegram папку не надіслати.

Якщо однойменна папка вже є, створюється окрема `Назва (2)`, `Назва (3)` тощо.
Наявні файли не перезаписуються. Файли передаються по одному, зі смугою прогресу
та лічильником. Перед початком перевіряються розміри, квота й структура.
На одну операцію — `FILES_MAX_UPLOAD_ITEMS` файлів і папок (типово 10 000),
до 32 рівнів вкладеності, список шляхів — до 16 МіБ; кожен файл обмежений `FILES_MAX_FILE_MB`, уся папка — вільним
місцем і `FILES_STORAGE_LIMIT_MB`. Порожні файли підтримуються. Вміст залишається
звичайними файлами в `blobs`, а структура папок — метаданими в SQLite.

При обриві вже збережені файли й створені папки залишаються, а повідомлення
показує кількість успішно переданих файлів. Автоматичного відновлення пакета немає:
можна дозавантажити решту файлів у потрібні папки. Повторний вибір усієї папки
створить нову копію з суфіксом. Під час передачі тримай сторінку відкритою.


## Перегляд і редагування документів

Кнопка **◉** біля файла або подвійне натискання на назву відкривають перегляд.
Скачування лишається окремою кнопкою **↓**. У модальному вікні можна також скачати
оригінал; нічого не передається зовнішнім сервісам чи ШІ для перегляду.

- **TXT/MD:** перегляд і редагування UTF-8-файлів до 1 МіБ. Натисни «Зберегти»,
  щоб змінити файл у сховищі. Зберігаються його номер для бота, назва й папка,
  а також BOM і стиль CRLF, якщо вони були. Markdown відкривається як вихідний
  текст; HTML і скрипти з документа не виконуються.
- **DOCX:** спрощений перегляд абзаців і таблиць. Зображення, колонтитули,
  точне оформлення та розбиття на сторінки не відтворюються.
- **XLSX:** перемикання аркушів, рядки й клітинки. Формули показуються текстом
  з кешованим результатом, якщо він є; вони не обчислюються. Дати й числове
  оформлення можуть відображатися як вихідні значення.
- **PDF:** вбудований переглядач браузера з підтримкою потокових запитів Range.
  Якщо на телефоні він не працює — відкрий PDF окремою вкладкою або скачай.
- **CSV/JSON/LOG:** текстовий перегляд, без редагування.

DOCX/XLSX — до 20 МіБ на документ, до 32 МіБ розпакованих даних; перегляд
обмежується 100 000 символів. Для DOCX — до 1000 блоків і до 200×30 клітинок
на таблицю; для XLSX — до 10 аркушів, 1000 рядків і перших 50 колонок на аркуш.
При обрізанні сайт показує відповідну позначку. Старі DOC/XLS і захищені паролем
документи потрібно скачати або конвертувати. Редагування Office/PDF не передбачено.

Збереження перевіряє версію: якщо файл уже змінили чи перейменували в іншій
вкладці, сервер повертає конфлікт, а локальний текст залишається в редакторі.
Скопіюй правки й відкрий актуальну версію для узгодження. Автозбереження та історії
версій немає. Під час помилки запису оригінал залишається чинним; новий файл спочатку
записується повністю, потім у транзакції оновлюється посилання в БД.

## Кількість файлів і папок у завантаженні

У `solution/.env`:

```env
FILES_MAX_UPLOAD_ITEMS=20000
```

Типове значення — 10000, допустимо 1–100000. Рахуються разом файли та всі папки
у вибраній структурі, включно з кореневою. Значення передається інтерфейсу з API;
після оновлення `.env` перезавантаж сторінку. Незалежно від цього залишаються
обмеження 16 МіБ на JSON-список шляхів, глибини 32 та квоти/диска. Для дуже великих
дерев за потреби завантажуй окремі підпапки. Дерево зліва спочатку показує лише
кореневі папки, стрілка ▸ розкриває наступний рівень за потреби.


## Файли через Guest Mode та звичайний чат Telegram

Відповідай на повідомлення з вкладенням, згадай бота й напиши команду:

```text
@DBresh_bot збережи в /Навчання/Лаби/
@DBresh_bot збережи за шляхом /Навчання/Лаби/
@DBresh_bot збережи як /Навчання/звіт.docx
```

Папки створюються автоматично. При збігу назв новий файл отримує `(2)`, `(3)`;
наявний вміст не перезаписується. Збереження повертає шлях і номер файла `#42`.
Повторна доставка того самого Telegram-запиту не створює другу копію.
Вкладення має бути в поточному повідомленні або в `reply_to_message`, яке
Telegram передав боту. Захищений вміст не копіюється. Якщо вкладення не надане —
перешли його боту. Документи, фото, відео, аудіо й голосові зберігаються як файли;
явна команда збереження має пріоритет над розпізнаванням голосу/зображень.

```text
@DBresh_bot надішли /Навчання/звіт.docx
@DBresh_bot надішли #42
@DBresh_bot покажи /Навчання/
@DBresh_bot знайди звіт
@DBresh_bot знайди через ші останню лабораторну про маршрутизацію
@DBresh_bot підсумуй /Навчання/звіт.docx
@DBresh_bot підсумуй #42
```

«Надішли» публікує файл у тому чаті, де викликали бота. При кількох збігах бот
показує шляхи й номери; повтори команду з конкретним `#номером`.
У приватному чаті з ботом згадка `@DBresh_bot` не потрібна.
Права перевіряються за `from.id` автора команди, а не автора вкладення; доступ
до спільного сховища мають лише `FILES_ALLOWED_USER_IDS`. Анонімні адміністратори
й повідомлення від імені каналів не отримують доступу.

Точні шляхи/номери, запис і надсилання обробляються кодом. ШІ-пошук отримує тільки
назви й шляхи обмеженого набору кандидатів (до 80 з бюджетом на розмір), а не
вміст документів. Бот повідомляє фактичну кількість переглянутих кандидатів.
Ідентифікатори, яких не було серед кандидатів, відкидаються; ШІ не може вибрати
файл поза whitelist або виконати довільну файлову команду. Аналіз вмісту за
`підсумуй` — окреме явне звернення до моделі, з тими ж форматами/лімітами, що `/file`.

Через стандартний Telegram Bot API вхідний файл для збереження — до 20 МБ,
нове вихідне завантаження — до 50 МБ. Ліміти сайта можуть бути більшими. Розміри
перевіряються і за метаданими, і за фактичним тілом відповіді при скачуванні.

### Telegram-кеш для надсилання через Guest Mode

Guest-відповідь із довільним вкладенням потребує Telegram `file_id`. Збережені
з чатів файли вже мають цей ID та можуть надсилатися одразу (документ із новою
назвою потребує повторного завантаження, щоб назва вкладення була актуальною).
Файли з сайта спершу завантажуються у приватний службовий канал:

```env
FILES_TELEGRAM_CACHE_CHAT_ID=-1001234567890
```

Створи приватний канал, додай бота адміністратором із правом публікувати файли,
вкажи числовий ID каналу. Канал міститиме технічні копії надісланих через нього
файлів; не додавай сторонніх учасників. Перше надсилання завантажує файл,
наступні використовують ID. Сайт і сховище залишаються закритими — публічних
посилань на двійкові файли для Telegram не створюється.

Щоб дізнатись ID: напиши щось у каналі, перешли це повідомлення в особистий чат
бота й відповідай на переслане командою `/channelid`. Бот покаже готовий рядок
для `.env`. Після оновлення конфігурації перезапусти `news-bot.service`.
Без налаштованого каналу бот попросить налаштування, а не надсилатиме файл
у приватний чат. Інші приватні чати для технічного кешування не використовуються.

Редагування або перейменування файла скидає чинність його кешу. Перед записом
нового ID також перевіряється версія, щоб одночасне редагування на сайті не
прив’язало старий Telegram-файл до нового вмісту. При протермінованому guest-запиті
немає пересилання в інший чат; збережений файл/кеш можна використати новою командою.

## Метрики для захисту лабораторної

```text
/stats
/stats 30
/stats csv
/stats csv 30
```

Доступ — лише whitelist. CSV надсилається у звичайному чаті з ботом; guest mode
може показати коротку статистику, але для експорту просить відкрити особистий чат.
Метрики починають збиратися після запуску нової версії; старі події не вигадуються.
БД — `solution/.runtime/usage.sqlite3`, виключена з Git і пакета розгортання.

| Метрика | Що саме вимірюється |
| --- | --- |
| Кількість повідомлень | Оброблені приватні та guest-запити, окремо необроблені винятки |
| Файлові операції | Спроби за командами, успіхи, відмови/помилки, неоднозначні результати |
| Успішність | Успішні спроби / усі спроби відповідної файлової команди; відмови доступу теж у знаменнику |
| Середній час і p95 | Від початку обробки до завершення операції/відповіді; черга до обробки не врахована |
| Байти | Фактичний розмір збереженого файла або переданого Telegram файла, включно з повторними надсиланнями |
| ШІ-виклики | Завершені виклики транспортного шару, успіх/помилка; внутрішні retry не рахуються окремо |
| Токени | Тільки `usage` провайдера або лічильники Ollama; відсутні значення не підміняються нулями |

CSV містить час Unix UTC, дію, статус, тривалість, байти, Telegram user_id,
контекст, призначення ШІ-виклику, модель і лічильники токенів. Там немає запитів,
відповідей, назв/шляхів файлів, секретів чи вмісту документів. User_id є персональним
ідентифікатором — для публічного звіту можна прибрати цю колонку.
Лічильник повідомлень означає факт обробки, а не правильну відповідь ШІ.
Успішне надсилання означає прийняття Telegram API, не прочитання людиною.
Статистика файлових команд не є лічильником усіх дій у вебінтерфейсі.

Для захисту достатньо показати реальну серію: 5 збережень, 5 надсилань, кілька
пошуків і аналізів, одну відмову доступу та один невдалий шлях; потім `/stats csv`.
Точність ШІ-пошуку оцінюй окремо: підготуй 10–20 запитів із наперед відомими
правильними файлами й порахуй частку випадків, де потрібний файл є в перших 5
результатах. Час «до/після» потребує окремого заміру ручного сценарію; автоматичні
метрики не доводять економію часу або якість відповідей. Існуючі оцінки економії
на голосових зберігаються окремо в `voice_runs` бази бота.
