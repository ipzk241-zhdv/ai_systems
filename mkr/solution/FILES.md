# Спільне сховище файлів

Вебсторінка дозволяє завантажувати файли з телефона/ПК, знаходити їх за назвою,
скачувати й копіювати команду для запиту до ШІ в Telegram. Усі дозволені користувачі
бачать одні й ті самі файли. Завантаження не запускає аналіз автоматично.

Інтерфейс працює як файловий менеджер: папки й підпапки, навігаційний шлях,
перейменування та переміщення через «⋮», список або плитки, сортування, пошук,
фільтри документів/зображень, завантаження кількох файлів із прогресом.
Наявні файли автоматично стають файлами кореневої папки, їхні номери не змінюються.

## Де налаштовувати

Локально: `mkr/solution/.env`. На поточній Oracle VM:
`/home/ubuntu/ai_systems/mkr/solution/.env`. Файл `.env.example` — приклад, його
редагування не змінює робочі параметри. Змінні середовища мають пріоритет над `.env`.

| Параметр `.env` | Що змінює | Типове значення |
| --- | --- | --- |
| `FILES_ENABLED` | Увімкнути сайт і команди сховища | `0` (вимкнено) |
| `FILES_ALLOWED_USER_IDS` | Дозволені Telegram user_id через кому | Порожній список |
| `FILES_PASSWORD_HASH` | Хеш спільного пароля; генератор нижче | Не заданий |
| `FILES_PUBLIC_URL` | Адреса сайта для посилань із бота | `http://127.0.0.1:8080` |
| `FILES_PORT` | Локальний порт вебсервера | `8080` |
| `FILES_STORAGE_LIMIT_MB` | Сумарний обсяг файлів, МБ | `5120` (5 ГБ) |
| `FILES_MAX_FILE_MB` | Максимум для одного файла, МБ | `100` |

Обсяг сховища можна встановити від 1 до 1 048 576 МБ, одного файла — від 1 до
1024 МБ. Це програмні верхні межі, а не гарантія наявності місця на VM. Місце наперед
не резервується; перед завантаженням також перевіряється фізично вільний диск із
резервом 64 МБ. Індикатор на сайті показує використаний обсяг, налаштовану квоту
й доступне місце з урахуванням диска. Зниження квоти не видаляє наявних файлів.

Після зміни порту, адреси чи максимального розміру файла перезапусти `news-bot`.
Зміни whitelist і хешу пароля перевіряються при кожному зверненні. Посилання на вхід
діє 5 хвилин, сесія — 2 години; ці технічні терміни поки задані в `file_store.py`.

## Команди

- `/id` — показати власний Telegram `user_id` (не `chat_id`).
- `/files` або «Файли» — список останніх файлів і посилання для входу на сайт.
- `/file 12 поясни головне` або `Файл 12: знайди суму витрат` — питання до файла №12.

Команди сховища працюють тільки в особистому чаті з ботом. У Guest Mode бот запропонує
перейти туди. Відповіді за файлами не потрапляють до звичайної історії чату в пам’яті;
наступне питання про файл теж надсилай через `/file`.

## Доступ

Список `FILES_ALLOWED_USER_IDS` містить числові ID, розділені комами. Кожна людина
дізнається свій ID командою `/id`. Бот бере особу з `message.from.id`, а не з тексту
запиту чи номера групи. Сховище не обмежує доступ до інших функцій бота.

`/files` видає дозволеному користувачу одноразове посилання на 5 хвилин. На сайті
потрібен ще й спільний пароль. ID не вводиться вручну: його вже підтвердив бот.
Посилання не пересилай іншим. Секретна частина розташована у фрагменті URL (`#access`),
не надсилається в HTTP URL і прибирається з адресного рядка після відкриття.

Сесія діє 2 години. Cookie має HttpOnly/SameSite=Strict, а для HTTPS — Secure.
Завантаження вимагає CSRF-токен і правильний Origin. Видалення ID зі списку одразу
закриває доступ і через сайт, і через бота; заміна хешу пароля завершує старі сесії.
Правила перевіряє Python-код перед відкриттям файла і перед зверненням до моделі.
ШІ отримує тільки вибраний файл/уривки, не має інструментів для довільного доступу
до диска, видалення файлів чи зміни прав. Вміст документів вважається недовіреними даними.

## Увімкнення на Oracle

Основний бот працює як раніше; сховище за замовчуванням вимкнене. Вебсервер і PDF
потребують Python 3.10+; на поточній VM використовується Python 3.12.

З каталогу `mkr` встанови окремі залежності (Ubuntu 24.04, без venv):

```sh
python3 -m pip install --user --break-system-packages -r solution/requirements-files.txt
```

Якщо pip ще не встановлений: `sudo apt install python3-pip`.
Наявний CI не встановлює нові додаткові залежності автоматично — це одноразовий крок.

Згенеруй хеш пароля командою з каталогу `mkr`:

```sh
python3 solution/file_store.py
```

Скрипт попросить пароль двічі, від 12 символів, і покаже рядок
`FILES_PASSWORD_HASH=...`. Скопіюй весь рядок буквально в `solution/.env` через редактор,
без виконання в shell. Пароль зберігається як PBKDF2-хеш із сіллю, не відкритим текстом.
Сам пароль передай дозволеним користувачам поза Git.

Додай в `solution/.env`:

```dotenv
FILES_ENABLED=1
FILES_ALLOWED_USER_IDS=123456789,987654321
FILES_PASSWORD_HASH=скопійований_рядок_хешу_без_повторного_FILES_PASSWORD_HASH
FILES_PUBLIC_URL=http://127.0.0.1:8080
FILES_PORT=8080
FILES_STORAGE_LIMIT_MB=5120
FILES_MAX_FILE_MB=100
```

ID вище — приклади; заміни їх реальними з `/id`. Рядок із хешем заміни результатом
команди цілком. Перезапусти той самий сервіс:

```sh
sudo systemctl restart news-bot
sudo systemctl status news-bot --no-pager
```

Вебсервер працює окремим потоком цього ж процесу, слухає **тільки 127.0.0.1:8080**.
Окремий daemon не потрібен, чинний systemd-сервіс може писати в `.runtime`.

## Поки немає домена

Публічний доступ із телефона ще потрібно окремо під’єднати через HTTPS. Для нього
знадобиться HTTPS reverse proxy/тунель, який передає запити на `127.0.0.1:8080` і
зберігає Host. Його зовнішню адресу вкажи як `FILES_PUBLIC_URL=https://адреса`.
У прикладі Caddy для власного домена достатньо `reverse_proxy 127.0.0.1:8080`.
Не публікуй порт 8080 напряму і не використовуй відкритий HTTP для пароля.

Перевірити сайт із комп’ютера до налаштування HTTPS можна SSH-тунелем:

```text
ssh -N -L 8080:127.0.0.1:8080 -i "D:\Downloads\ssh oracle\ssh-key-2026-11-17.key" ubuntu@141.147.21.157
```

Залиш цю консоль відкритою, надішли боту `/files` і відкрий отримане посилання
`http://127.0.0.1:8080/#access=...` на цьому ж комп’ютері. Для цього режиму в `.env`
залишай локальний `FILES_PUBLIC_URL`. Звичайний публічний HTTP конфігурація відхиляє.

## Формати й обмеження

Зберігати/скачувати можна будь-які файли: типово до 100 МБ на файл і 5 ГБ на все сховище;
обидва обмеження змінюються в `.env`. Передача й запис ідуть частинами, без утримання
всього великого файла в пам’яті. Максимальна вкладеність папок — 32 рівні.
ШІ підтримує UTF-8 TXT/MD/CSV/JSON/LOG, PDF із текстовим шаром, DOCX та JPEG/PNG/WebP
(картинки для аналізу до 8 МБ). Скановані PDF спочатку перетвори на картинки.
Архіви, програми та інші формати тільки зберігаються — сервер їх не виконує.
Видалення файлів у цій версії ще немає.

Для великих документів витягується не більше 100 000 символів; модель отримує до
5000 символів вибраних за словами запитання. Бот явно позначає аналіз за уривками.
Це простий пошук фрагментів, не гарантія аналізу всього документа. Для повної перевірки
великої таблиці/документа розбий його на частини й перевір важливі числа самостійно.
Текстові документи використовують звичайний LLM_PROVIDER/LLM_MODEL, картинки —
Groq/VISION_MODEL. Вибраний вміст передається відповідному провайдеру лише за командою.

Файли лежать під випадковими назвами в `solution/.runtime/files/blobs`, метадані,
хеші посилань і сесій — у `solution/.runtime/files/files.sqlite3`. Оригінальна назва
ніколи не використовується як шлях на сервері. PDF/DOCX читаються окремим процесом
із таймаутом, а на Linux також з обмеженням пам’яті й CPU.
Файли, БД і `.env` не входять у Git/ZIP-пакет. Наявні резервні копії новин не є
резервною копією сховища — для важливих матеріалів потрібна окрема копія `.runtime/files`.
