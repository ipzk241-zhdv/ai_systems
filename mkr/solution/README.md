# Ранковий дайджест Житомира, України і світу

## Спільне сховище файлів

Додано необов’язковий вебфайлменеджер зі входом за посиланням із бота та паролем.
Доступ мають тільки дозволені Telegram `user_id`; файли спільні для них усіх.
`/id` показує власний ID, `/files` відкриває сховище, `/file 12 питання` передає
вибраний документ ШІ. Завантаження файла саме по собі не запускає аналіз.
Сховище вимкнене за замовчуванням. Налаштування й обмеження описані в [FILES.md](FILES.md).

## Фоновий збір та підготовка новин

`NEWS_POLL_MINUTES=1` задає інтервал між завершенням підготовки й наступним
фоновим запуском (ціле число 1–1440). Нове типове значення — 1 хвилина.
Якщо в наявному `.env` залишилось `10` або `30`, зміни його явно та перезапусти бота.

Перший запуск збирає публікації за останні 24 години й заповнює кеш оцінок.
Далі дозбирається лише пропущений проміжок; приблизно раз на 30 хвилин
повторно перевіряється вся доба, щоб підхопити запізнілі публікації та зміни.
Помилки джерел не видаляють останній добрий кеш. Якщо нічого нового немає,
повторних ШІ-запитів немає.

У `news_annotations` зберігаються **всі чотири категорії, включно зі skip**, зв’язок
new/repeat/update та посилання на попередню публікацію. Ключ кешу містить
провайдера, модель, версію підготовки, промпт і персональні правила.
Зміна моделі/правил перераховує відповідні оцінки; попередні версії залишаються.
Зміна заголовка за тим самим URL створює новий запис статті й нову оцінку.

ШІ обробляє новини пакетами до 8. Для зіставлення подій отримує лише невеликий
набір схожих заголовків серед до 240 вже підготовлених публікацій. Це скорочує
повторення контексту, але не гарантує знаходження всіх перефразованих дублів.
Класифікація та зв’язки подій тепер визначаються разом; налаштування особистої
важливості з `importance.txt` залишаються чинними. Автоматичного донавчання
за ручними оцінками не виконується.

За кнопкою бот перевіряє пропущений проміжок збору й бере оцінки з БД. Якщо
для частини новин їх немає — **одразу запускає позапланову підготовку**, чекає
її завершення й тільки тоді формує повний дайджест. Якщо та сама підготовка вже
працює у фоні, запит чекає на неї й повторно використовує записаний результат;
одна новина не оцінюється паралельно двічі в одному процесі.

Позапланова підготовка зміщує спільний таймер: наступний прохід — через
`NEWS_POLL_MINUTES` після завершення, а не за старим дедлайном. Вдалий пакет
зберігається одразу. Після помилки повторюються лише ще неготові пакети;
при квоті/помилці API дані не вважаються оціненими й повний дайджест не
маскується неперевіреними категоріями.

Для готових оцінок ШІ під час запиту не викликається. Відбір за періодом,
перевірка вже показаних цьому користувачу новин і збирання HTML виконуються
кодом. Оновлення зіставляється з уже надісланим попередником, повтори вже
отриманих подій приховуються. Кеш спільний, історія отримання — окрема для чату.
Індекси теж беруться з фонового кешу, який оновлюється раз на 15 хвилин.

Помилка Groq `json_validate_failed` відрізняється від помилки ключа чи моделі.
У такому разі пакет автоматично ділиться 8 → 4 → 2 → 1; вдалі частини відразу
зберігаються. Для однієї новини є ще одна обмежена спроба зі спрощеною серверною
схемою, але точні категорії, структура й посилання завжди перевіряються кодом.
Неприпустима категорія не підміняється вигаданою `news` і не потрапляє в кеш.
Якщо відновлення не допомогло, решта готових оцінок лишається в БД, а повідомлення
просить повторити підготовку. Квота, авторизація, мережеві та інші конфігураційні
помилки не запускають це ділення; зайвих спроб для них немає. Відновлення формату
може витратити додаткові запити й токени. Уже коректний кеш не скидається.


Перший прогрів, зміна правил або великий пропущений проміжок ще можуть тривати
хвилини. Дозбір сайтів і надсилання файла теж потребують мережі; готовий кеш
прибирає основну повторну ШІ-роботу, але не обіцяє фіксованої затримки в секундах.
Тривалість, кількість підготовлених записів і помилки записуються в
`news_preparation_runs`, LLM-виклики — у звичайні метрики використання.

## Картинки

Надішли фото або JPEG/PNG/WebP-файл до 8 МБ в особистий чат бота. Підпис стане
запитанням до картинки; без підпису бот опише зображення і прочитає видимий текст.
Можна відповісти на картинку текстовим запитанням. У групах і чатах з іншими людьми
відповідай на картинку повідомленням `@DBresh_bot що тут написано?` або просто `@DBresh_bot`.
Потрібен Guest Mode або присутність бота в групі. Аналізується одна картинка за запит.

Використовується Groq із наявним `GROQ_API_KEY` та окремою моделлю
`VISION_MODEL=qwen/qwen3.8-27b` (це типове значення; змінювати `.env` необов’язково).
Текстовий `LLM_MODEL` залишається окремим. Картинки передаються Groq як байти через
base64, без Telegram-посилань із токеном, і не записуються на диск. У приватному чаті
для наступних запитань зберігаються лише перші 3500 символів відповіді моделі в пам’яті.
Для повторного розгляду деталей відповідай саме на початкове фото. Довга відповідь у
приватному чаті надходить HTML-файлом, у Guest Mode скорочення позначається явно.

Кнопка «Відключення» показує погодинний графік і підказку для пошуку своєї вулиці,
без переліку перших п’яти вулиць. Приклад пошуку: `Відключення: Михайла Грушевського`.

Скрипт збирає заголовки, час і прямі посилання з вебсайтів. Локальна Qwen відбирає важливе й отримує завдання вибрати один заголовок, якщо ту саму подію висвітлили кілька разів. Скрипт підставляє оригінальні заголовки та адреси за ідентифікаторами публікацій.

## Запуск

Потрібні Python 3.8+, `curl` і запущений [Ollama](https://ollama.com/download). У Windows `curl` зазвичай уже встановлений. Виконай з кореня репозиторію.

```console
python -m pip install -r mkr/solution/requirements.txt
ollama pull qwen3.5:9b
python mkr/solution/digest.py
```

Файл `digest.md` з’явиться в поточній теці. Типове вікно — від 22:00 до 08:00 за Києвом. При запуску вночі вікно закінчується в момент запуску. Для ширшої вибірки запусти з `--hours 24`. `--collect-only` показує кількість новин та помилки за джерелами без звернення до Ollama.

## Telegram-бот

Для хостингу на Oracle з AI-запитами через Groq дивись [інструкцію розгортання](../deploy/README.md).
Цей режим не потребує Ollama на сервері; провайдер задається в `.env`.

Відкрий консоль у папці `mkr`. Установи залежності один раз:

```console
python -m pip install -r solution/requirements.txt
```

Коли Ollama запущено і Qwen3.5 9B завантажено, запускай:

```console
python start_bot.py
```

Бот працює у відкритій консолі, де видно його повідомлення. Для зупинки натисни `Ctrl+C` або закрий це вікно. Для повторного запуску виконай ту саму команду.

Токен зчитується з `TELEGRAM_BOT_TOKEN` у середовищі або з рядка `TELEGRAM_BOT_TOKEN=…` у локальному файлі `solution/.env`. Цей файл виключено з Git. Відкрий бота в Telegram і натисни **Start**. Бот доступний усім, хто відкриє з ним приватний чат.

Кнопки **За 4 години**, **За 8 годин** та **За 24 години** рахують період від моменту початку запиту. **З останньої перевірки** збирає новини з початку попереднього запиту в цьому чаті, на який бот успішно надіслав результат. Вікно обмежене 24 годинами. Перший запит цією кнопкою охоплює останні 24 години. Час перевірки зберігається окремо для кожного чату в локальній базі `.runtime/bot-<id>.sqlite3`.

У базі зберігаються заголовки, URL, час публікації, HTML-дайджести та кеш оцінок. Повтори й оновлення подій готуються у фоні за заголовками; зміни тільки всередині тексту можуть лишитися непоміченими. Для конкретного чату перевіряється історія реально надісланих новин за сім днів, а оновлення містить попередній заголовок і посилання.

Показаними вважаються новини з успішно надісланих файлів. Якщо надсилання завершилося помилкою, повторний запит знову може їх включити. Історія зберігається після перезапуску, а запити різних чатів мають окрему історію показаного.

Бот використовує ті самі джерела й ту саму модель, що й Markdown-версія. У відповідь надсилає автономний HTML-файл із розділами, часом публікації та прямими посиланнями. Його можна завантажити й відкрити в браузері. Блок ринків показує відсоткові зміни фондів SPY, QQQ і DIA за останню доступну сесію за даними [NineQuantAI](https://ninequantai.com/en/api#data-timeliness).

Відредагуй [importance.txt](importance.txt), щоб змінити, які події потрапляють у «Важливе», звичайну стрічку чи «Цікаве й смішне», а які пропускаються. Нові критерії діють із наступного запиту дайджесту.

Кнопка **Відключення** показує опубліковані інтервали для 12 підчерг на сьогодні та завтра, якщо є графік, і перші п’ять діючих записів по місту Житомиру. Для пошуку за вулицею напиши `Відключення: Київська`. Бот читає [таблицю графіка](https://www.ztoe.com.ua/unhooking-search.php) і JSON із публічних запитів [сторінки діючих відключень](https://ztoe-poweron.inneti.net/). Обидва запити працюють без Ollama. Графік показує заплановані інтервали, а записи API — стан, який опублікувало обленерго, з очікуваним часом відновлення.

Щоб поставити запитання, просто напиши в той самий чат. Можна надіслати окреме слово, як-от «канделябр», або написати «Що означає слово “манівці”?». Бот шукає такі слова в [СУМ-11 на Slovnyk.me](https://slovnyk.me/dict/sum/манівці). Інші запити, наприклад «Дай простий рецепт борщу», обробляє локальна Qwen3.5 9B. Для уточнень бот тримає в оперативній пам’яті до трьох попередніх обмінів у кожному з 32 останніх активних чатів. Після перезапуску ця історія очищується. Для свіжих новин скористайся кнопками.

## Пояснення і порівняння новин

Новини в HTML мають наскрізні номери. Напиши **«Поясни 3»** або
**«Поясни 3: що це означає для мешканців?»**. Номер береться з останнього
успішно надісланого дайджесту саме цього чату. Бот завантажує текст статті,
зберігає його в SQLite і передає Qwen разом із запитанням. Відповідь містить
посилання на джерело. Якщо текст недоступний, бот повідомляє про це.

Кнопка **«Що змінилося»** (або такий самий текст у чаті) порівнює два останні
успішно надіслані випуски за збереженими заголовками. Це огляд нових тем і змін,
а не перевірка повних текстів усіх статей. Зіставлені оновлення можуть посилатися
на раніше показану новину за останні 7 днів. Відсутність теми у новому випуску
не означає, що подія завершилася. Історія доступна після перезапуску бота.

## Guest Mode: надіслати згадку й отримати відповідь від бота

У звичайному приватному чаті з іншою людиною або в групі напиши
`@DBresh_bot поясни, що таке API` і **надішли повідомлення**. Бот опрацює запит
і відповість у цьому чаті від власного імені. Обирати inline-результат не потрібно.

Власник вмикає **Guest Mode** в Mini App керування ботами `@BotFather` → бот → Settings.
Це окрема опція від Inline Mode. Telegram підтримує гостьові відповіді в несекретних
приватних чатах, групах і супергрупах без захисту контенту; бот може відповідати,
навіть не будучи учасником. Потрібен Telegram-клієнт із підтримкою цієї функції.

Обробляються текст запиту (до 1500 символів) і, якщо Telegram передав його,
уривок повідомлення, на яке користувач відповів. Повної історії чату та приватних
дайджестів бот не отримує. Гостьовий режим не читає SQLite-історію. Не передавай
у згадці повідомлення, які не хочеш надсилати Groq. Фото та інші вкладення поки не аналізуються.

Кожен гостьовий запит отримує одну відповідь через `answerGuestQuery`. Навіть коли
Telegram передає числовий chat ID, він не використовується для `sendMessage` у гостьових
відповідях: це окремий контекст доступу. У групах, де бот уже учасник і Telegram доставляє
звичайне повідомлення зі згадкою або відповіддю боту, він надсилає звичайну відповідь із цитатою.
Інші повідомлення групи та повідомлення від ботів ігноруються.

Новинний дайджест і команди на кшталт `Поясни 2` залишаються в особистому чаті з ботом.
Опис Telegram: https://core.telegram.org/bots/features#guest-bots

## Inline mode: попередній перегляд відповіді

Напиши `@DBresh_bot поясни, що таке OCPU`, дочекайся результату й натисни на нього,
щоб надіслати відповідь у поточний чат. Додавати бота до групи не потрібно.
Inline-режим вмикається власником через `@BotFather` → `/setinline`.

Це короткі окремі запитання до ШІ: без історії співрозмовників, приватної історії
бота чи доступу до збережених дайджестів. Новини та `Поясни 2` використовуй у приватному чаті.
Для inline-запиту діє обмеження 400 символів. Кеш відповідей окремий для кожного користувача;
повторний запит протягом кількох хвилин не потребує нової генерації. Пауза під час набору
об'єднує швидкі зміни запиту. Тривала пауза з неповним запитом теж може спричинити генерацію.

Якщо Groq зайнятий, ліміт вичерпано або відповідь не встигає в короткий термін,
з'являється кнопка переходу в приватний чат. Inline-запити не чекають хвилинного
скидання квоти й не блокуються збором новин. Звичайні повідомлення обробляються
послідовно окремим робочим потоком із власним SQLite-з'єднанням.

## Розшифровка голосових

Надішли або перешли голосове в особистий чат бота — отримаєш лише повідомлення
**«Розшифровка»** з текстом, без повідомлення про початок і без статистики в чаті.
Для дуже довгого тексту приватний бот надсилає один HTML-файл замість багатьох повідомлень.

У групі або звичайному приватному чаті з іншою людиною достатньо **відповісти на голосове
повідомленням `@DBresh_bot`**. Слово «розшифруй» не потрібне. Потрібен увімкнений Guest Mode;
бот використовує голосове з контексту відповіді, який передає Telegram, без читання історії чату.
У групі, де бот є учасником, також обробляється звичайна згадка у відповіді на голосове.
Якщо Telegram не дає доступу до аудіо, його можна переслати в особистий чат бота.

Guest Mode дозволяє одну відповідь. Якщо текст не вміщується в одне повідомлення,
бот попросить переслати голосове в особистий чат для отримання повного тексту файлом;
обрізаний текст не видається за повний і такий випадок не додається до успішної статистики.
Розпізнавання виконує Whisper через Groq, а не звичайна текстова модель.

Потрібен наявний `GROQ_API_KEY` із доступом до аудіомоделі, навіть якщо текстовий чат
налаштований на Ollama. Нові параметри необов’язкові — наведені типові значення:

```dotenv
STT_MODEL=whisper-large-v3-turbo
STT_LANGUAGE=
READING_WPM=200
PLAYBACK_SPEED=1
```

Порожній `STT_LANGUAGE` означає автовизначення; `uk` — українську. Можна також обрати
`STT_MODEL=whisper-large-v3`. Перша версія підтримує голосові до 10 хвилин і до 19 МБ.
Для звичайних OGG/Opus-голосових Telegram окреме встановлення ffmpeg не потрібне.
Діють аудіоквоти Groq.

Формула: `D / s − P − 60 × W / r`, де D — секунди аудіо, s — швидкість прослуховування,
P — час від отримання ботом до надсилання тексту, W — слова в розшифровці,
r — припущена швидкість читання у словах/хв. Результат, зокрема від’ємний, зберігається
тільки в БД. Це оцінка, не вимірювання особистої швидкості читання. Вона не включає
початкове пересилання з телефона в Telegram і час на виправлення розпізнавання.

Числові показники автоматично зберігаються в таблиці `voice_runs` у наявній runtime-базі
після успішного надсилання повного тексту. Поле `context` розрізняє `private`, `group` і `guest`.
Старі записи залишаються; новий стовпець додається автоматично зі значенням `private`.
Код не записує аудіо й повну транскрипцію на диск. У пам’яті чату залишається до 3500
символів для наступних запитань; якщо текст довший, це позначається як уривок.
Аудіофайл передається Groq без Telegram-посилання, яке містило б токен бота.
Імена, числа й важливі деталі перевіряй за оригіналом.

Нових Python-залежностей немає. Наявний CI запускає також `test_voice.py`.
Перед використанням перевір кілька справжніх голосових: автоматичні тести перевіряють
код з імітацією API, а не точність моделі на твоїх записах.
Документація сервісу: https://console.groq.com/docs/speech-to-text

## Персональний відбір: потрібність і позначки

Новий фоновий конвеєр використовує три рішення: `skip` — пропустити, `news` —
показати, `important` — важливе. Окремо зберігає `tags`: `funny` (кумедне),
`interesting` (цікаве), `positive` (позитивне). Хороші для України новини не
прирівнюються до гумору. Новина може бути важливою й позитивною одночасно.
Для пропущеної новини список позначок порожній. У HTML вони видимі окремими
значками; за великого списку до трьох позначених новин отримують місця після
важливих, як раніше отримувала група fun. Це не примусове заповнення дайджесту.
Старі дайджести й старі рядки оцінювання залишаються читабельними.

`importance.txt` містить персональні правила, негативні приклади й пояснення
позначок. `news_examples.json` містить усі 100 ручних оцінок із 3 прямими уточненнями
користувача. Для мінітесту використовувалися лише 63 приклади (60 + 3), а після
фіксації результату до робочого профілю перенесено решту. Для старого `fun` переноситься лише
рішення «показати», без вигадування окремої людської оцінки гумору/позитиву.
За точного збігу URL і заголовка пряма людська оцінка має пріоритет над моделлю.
Відомий людський skip записується без ШІ-запиту. У БД це позначено
`decision_source=human_exact`, щоб не приписувати такий результат самій моделі.
Зміна заголовка скасовує прямий збіг. Нові новини оцінюються моделлю.
Локальний пошук підбирає до шести схожих прикладів, із різними рішеннями й
обмеженим обсягом. Службові id прикладів не є id попередників подій.

Заголовки/коментарі — дані, не команди. Код перевіряє всі категорії, позначки й
зв’язки перед записом у БД. Промпт обмежений 15 000 UTF-8 байтів: якщо контекст
завеликий, прибираються зайві приклади/попередники або ділиться пакет. Версія кешу
враховує промпт, модель, правила й файл прикладів. `tags_json` додається міграцією
без видалення старих оцінок.

Модель новин можна вибрати незалежно від звичайного чату:

```env
LLM_MODEL=openai/gpt-oss-20b
NEWS_MODEL=openai/gpt-oss-120b
```

Порожній/відсутній `NEWS_MODEL` використовує модель чату. Зміна потребує
перезапуску. Оновлення правил/прикладів спричиняє новий прогрів кешу; це додаткові
запити й токени. Приклади підвищують розмір контексту, тому фоновий кеш залишається
потрібним. Модель не донавчається: це персональні інструкції та локальний добір
прикладів. Старий консольний шлях `digest.py` зберігає сумісний формат із fun;
нові незалежні позначки використовує фоновий конвеєр Telegram-бота.

Під час перевірки було відкладено окремі 20 новин без включення в приклади.
Після фіксації мінітесту вони включені у робочі 100; повторний тест на них уже
не буде незалежним. Для наступного вимірювання потрібні нові новини. Ще 20 були
робочою вибіркою; після уточнення трьох випадків вони не є незалежним тестом.
Усі 100 новин уже переглядалися під час початкового аналізу, а схожі події можуть
зустрічатися в різних частинах. Мінітест є попереднім порівнянням, а не доказом
узагальненої точності. Наступну фінальну оцінку варто проводити на нових новинах.
Старе fun для порівняння потрібності приводиться до news; точність нових позначок
на старій розмітці не рахується, бо таких людських міток ще немає.
